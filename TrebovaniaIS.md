**1 Описание предметной области**

Разрабатываемый веб-сервис принимает от пользователя одну фразу, самостоятельно извлекает из неё ключевые параметры поездки (город, даты, число гостей, бюджет, пожелания) и возвращает готовую подборку отелей. Для анализа отзывов привлекается внешняя языковая модель (LLM), которая формирует краткую выжимку: 2–3 главных плюса и 1–2 реальных минуса.

Название предметной области: Интеллектуальный подбор отелей и апартаментов по запросам на естественном языке.

Название информационной системы и её граница: «hotel_assist» — веб-сервис интеллектуального поиска отелей. В границу системы входят: модуль приёма и сохранения запросов, хранилище истории запросов. Внешняя среда: пользователь, сервис LLM (распознавание смысла запроса и анализ отзывов), сайты бронирования (источник актуальных карточек отелей).

**2 Глоссарий**

Пользователь – человек, использующий сервис hotel_assist для подбора жилья посредством текстовых запросов.

Запрос – произвольное текстовое сообщение на естественном русском языке с пожеланиями к поиску отеля (город, даты, бюджет, число гостей, дополнительные условия).

Параметры поиска – структурированные данные, извлечённые из текста запроса: город, даты заезда и выезда, число гостей, ценовой диапазон, пожелания.

История запросов – сохранённый перечень ранее введённых пользователем запросов, доступный ему после авторизации.

LLM (большая языковая модель) – внешний сервис искусственного интеллекта, распознающий смысл текстового запроса и анализирующий отзывы об отелях.

Выжимка отзыва – краткое резюме, формируемое LLM по массиву отзывов: 2–3 главных плюса и 1–2 реальных минуса объекта размещения.

Сайт бронирования – внешний веб-ресурс, содержащий актуальные данные об отелях и выступающий источником карточек для сервиса.

Отель (гостиница) – объект размещения, предоставляющий номера для временного проживания.

Апартаменты – объект размещения квартирного типа с кухней и жилыми помещениями.

Авторизация – процедура подтверждения личности пользователя по логину и паролю для доступа к истории запросов.

БД – база данных.

СУБД – система управления базой данных.

ИС – информационная система.

ИИ – искусственный интеллект.

  

**3**        **Концепция**

Информационная система hotel_assist должна предоставлять возможность:

-         пользователю авторизоваться в системе;

-         пользователю написать запрос на поиск жилья в произвольной текстовой форме;

-         пользователю просмотреть отели — готовую подборку вариантов, соответствующих запросу;

-         пользователю просмотреть карточку отеля с выжимкой плюсов и минусов по отзывам;

-         пользователю посмотреть свои ранее сохранённые запросы;

-         Создаваемая ИС будет работать с собственной базой данных под управлением СУБД PostgreSQL:

-         в режиме доступа без обновлений при просмотре отелей и истории запросов;

-         в режиме доступа с обновлениями при авторизации пользователя и сохранении запросов в историю.

Поиск и просмотр отелей доступны без авторизации. Для авторизации необходимо указывать логин и пароль; авторизация открывает доступ к истории запросов.  

**4 Нефункциональными требованиями к ИС**

-         Требования к применению:

1)    ИС должна быть доступна через любой современный веб-браузер без установки дополнительного ПО;

2)    Интерфейс поиска должен быть понятен пользователям любой возрастной категории, включая людей, не привыкших к сложным сайтам;

3)    ИС должна поддерживать адаптивный интерфейс для настольных компьютеров и мобильных устройств.

-            Требования к производительности:

1)    Точность распознавания параметров поездки (город, даты, число гостей, бюджет) должна составлять не менее 90% запросов;

2)    Отображение карточек отелей должно выполняться в 100% случаев, в том числе при отсутствии у объекта отзывов;

-            Требования к реализации:

1)    ИС должна взаимодействовать с БД через СУБД PostgreSQL;

2)    Пользовательская часть ИС должна быть реализована с использованием HTML5, CSS3 и JavaScript;

3)    Серверная часть ИС должна быть реализована с использованием языка Python (фреймворк FastAPI);

4)    Взаимодействие с LLM и сайтами бронирования должно осуществляться по API через протокол HTTPS;

5)    ИС должна быть кроссплатформенной.

-            Требования к интерфейсу:

1)    Интерфейс ИС должен быть веб-ориентированным с единой строкой ввода запроса в стиле диалога;

2)    Интерфейс ИС должен удовлетворять современным требованиям к оформлению сайтов;

3)    Карточка отеля должна содержать наглядно разделённые блоки плюсов и минусов из выжимки отзывов.

-            Требования к безопасности:

1)    Передача информации между клиентом и сервером, а также между ИС и внешними сервисами должна производиться в зашифрованном виде (протокол HTTPS);

2)    ИС не должна сохранять в открытом виде персональные данные пользователей, вводимые в строку поиска;

3)    Доступ к истории запросов должен предоставляться только авторизованному пользователю и только по его собственным запросам;

4)    ИС должна обеспечивать защиту от SQL-инъекций, XSS- и DDoS-атак.

  

**4**        **Действующие лица ИС**

Действующими лицами ИС являются:

-         Пользователь — человек, который авторизуется, пишет текстовые запросы на поиск жилья, просматривает подобранные отели и свою историю запросов;

-         LLM — внешний сервис языковой модели; распознаёт смысл запроса, извлекает параметры поиска, исправляет опечатки и формирует выжимку плюсов и минусов по отзывам;

-         Сайт бронирования — внешний веб-ресурс; предоставляет системе актуальные карточки отелей (фотографии, описания, адреса, цены, наличие мест), отображаемые при просмотре отелей.  

**6 Функциональные требования к ИС**

Пользователю доступны следующие возможности:

1)       авторизация;

2)       написать запрос на поиск жилья в произвольной текстовой форме;

3)       просмотреть отели — подборку вариантов, соответствующих запросу, и карточки отелей с выжимкой отзывов;

4)       посмотреть свои сохранённые запросы.

LLM обеспечивает системе следующие возможности:

1)       извлечение параметров поиска (город, даты, число гостей, бюджет, пожелания) из текста запроса;

2)       исправление опечаток и разговорных формулировок в названиях городов с последующей сверкой со справочником;

3)       анализ отзывов об отеле и формирование выжимки: 2–3 главных плюса и 1–2 реальных минуса.

Сайт бронирования обеспечивает системе следующие возможности:

1)       предоставление актуальных карточек отелей (фотографии, описания, адреса, цены, наличие мест) при просмотре отелей.

Системные ограничения и поведение в нестандартных ситуациях:

1)       если в запросе не указан город, система выводит вежливое уточнение (_«Пожалуйста, подскажите, в каком городе вы ищете отель?»_), а не сообщение об ошибке;

2)       при размытом бюджете (_«недорого», «подешевле»_) система сортирует варианты от самых доступных либо отбирает отели не дороже средней стоимости по городу;

3)       при сроках без точных дат (_«на выходные», «на 3 дня»_) система рассчитывает даты автоматически от текущей даты сервера;

4)       если у отеля нет отзывов, карточка отображается с базовой информацией без блока плюсов и минусов, страница не зависает;

5)       поиск и просмотр отелей доступны без авторизации; просмотр истории запросов — только после авторизации.
